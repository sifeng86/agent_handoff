# Spec: JWT auth (rev 2)

Author: planner (claude-opus-5-5@claude-a/host-1)
Based on: docs/handoff/2026-11-04-plan-jwt.md

## 1. Scope
As plan §2.

## 2. Config
- `JWT_SECRET` required; server exits with a clear error if missing.
- Token TTL: 15 minutes.

## 3. Steps
- **S1** `POST /login` returns `{token}` on valid credentials.
- **S2** Middleware on all `/api/*` routes, **except `/api/health`** (rev 2, see question-jwt-health).
- **S3** Tests (§5) and README section.

## 4. Errors
401 body: `{error: {code: "UNAUTHORIZED", message}}`, matching src/api/errors.ts.

## 5. Acceptance Criteria
| # | Criterion | Verify |
|---|---|---|
| A1 | Valid login returns a token | `pnpm test -- auth.login` |
| A2 | Missing/invalid/expired token → 401 with §4 body | `pnpm test -- auth.middleware` |
| A3 | `/api/health` works without a token | `pnpm test -- health` |
| A4 | Missing `JWT_SECRET` → startup fails | `pnpm test -- config` |
| A5 | Typecheck clean | `pnpm typecheck` |

## 6. Stop Conditions
- Existing auth code found that conflicts with this spec → stop, ask planner.

| Finding | Decision | Reason |
|---|---|---|

| R2 | accepted | §4 follows existing error format |
| R3 | accepted | §3 S2 lists route scope |
