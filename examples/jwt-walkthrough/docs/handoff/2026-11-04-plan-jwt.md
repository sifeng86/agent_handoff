# Plan: JWT auth

Author: planner (claude-opus-5-5@claude-a/host-1)

## 1. Goal
Protect API routes so only logged-in users can call them.

## 2. Scope
- In: `POST /login` issues a token; middleware validates it on protected routes.
- Out: refresh tokens, roles/permissions, logout.

## 3. Approach
- HS256, secret from env `JWT_SECRET`. Single service, no key distribution needed.
- Middleware rejects missing/invalid/expired tokens with 401.

## 4. Steps
1. Token issue on login.
2. Middleware + route wiring.
3. Tests and docs.

## 5. Risks
- Secret missing at startup → must fail fast, not run unprotected.
